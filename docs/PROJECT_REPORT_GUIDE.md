# Mini-project report outline

Use this as a structure, not a claim that the report or contributions are finished.

1. **Title and team:** Blood Bank Management System; two members; instructor approval and section-unique title.
2. **Problem statement:** Track donations, screening, stock and hospital demand without inconsistent or duplicate issuance.
3. **Objectives and scope:** Demonstrate DBMS concepts, with a minimal desktop localhost interface. State classroom simplifications.
4. **Requirements:** Map the supplied PDFs to SQL design, second paradigm, four-plus advanced SQL concepts, Mongo aggregation, Next.js, two roles and validation.
5. **ER model:** Include the Chen diagram and explain entities, attributes, relationships, cardinalities and participation.
6. **Relational conversion:** Include relational schema, PK/FK/UNIQUE keys, dependencies and normalization. Disclose maintained redundant columns.
7. **Database choices:** Explain transactional MySQL data versus nested versioned MongoDB questionnaire documents.
8. **Data dictionary and implementation:** Use DATA_DICTIONARY.md; explain DDL, constraints, views, indexes, triggers, function and procedure.
9. **Important queries:** Select representative JOIN, aggregation/HAVING, subquery, DML and transaction examples; explain outputs using your own run.
10. **Architecture:** Desktop browser → Next.js page → route handlers → MySQL; screening documents → MongoDB. Credentials stay in .env.
11. **Application screenshots:** Capture your own login, stock, request issue and database reports. A few desktop screenshots are enough.
12. **Testing:** Record expected/actual results from WORKFLOW_AND_TESTS.md. Keep failed cases and fixes; do not invent passing evidence.
13. **Individual contributions:** Both members must contribute to database and application work. Link genuine commits.
14. **Conclusion / future enhancements:** What DBMS concepts were learned; limitations; optional future work, not promised implemented features.
